### 项目本质
Cogita = 基于 Rspress 的「主题驱动」静态博客框架。核心理念：主题不仅是视觉皮肤，而是声明自身插件依赖的完整生态，实现「写 `theme: 'lucid'` 一个字段即开箱即用」。

### 架构核心链路（core/src/node/config.ts）
`cogita dev` → `loadCogitaConfig`(findUp+jiti 加载 cogita.config.ts) → `createRspressConfig`：
1. 主题别名解析（'lucid'→'@cogita/theme-lucid'，从 core 包位置用 mlly.resolve 解析）
2. 调用 `theme.getThemeConfig()` 拿到 CogitaTheme
3. `createFullConfig` 注入默认值+_framework 元信息 → CogitaPluginConfig
4. 遍历 `theme.plugins`(CogitaPluginFactory[]) 实例化，strict 模式失败抛错
5. `createThemePlugin` 把 globalStyles/globalUIComponents/pageLayouts.home 包装成 RspressPlugin
6. 交给 @rspress/core 的 dev/build，docDirectory 用虚拟目录 `.cogita_content` 规避文件路由

## tag 页面 React 组件方案（解决页面空白 + 孤儿组件）

用户 review 发现 tag 详情页空白。排查：rspress dev 模式对 addPages 纯 markdown content（无 filepath）渲染为空。同时 A/B 确认 TagList import @cogita/shared 导致首页空白（rspress 客户端无法 resolve shared 包，shared 原为纯类型包）。

### 根因
1. tag 页面用 addPages 生成 markdown content（无 filepath）→ rspress 渲染空
2. TagList import @cogita/shared 运行时函数 → rspress 客户端 bundle 无法 resolve → 首页空白
3. TagCloud/TagList 成孤儿（markdown 页面无法用 React 组件）

### 解决方案：tag 页面改 React 组件
**架构改动**：tags 插件 addPages 不再生成 markdown，改为 filepath 指向主题 TagPageLayout 组件。
- **shared**：CogitaPluginConfig 加 themeLayouts 字段；CogitaTheme.pageLayouts 加 tag/tagIndex；补 globalUIComponents
- **core**：createRspressConfig 注入 themeLayouts（解析 themeDir + pageLayouts 为绝对路径）到 fullConfigForPlugins；CogitaFullConfig 加 themeLayouts
- **lucid**：新增 src/layouts/Tag.tsx（TagPageLayout）消费 virtual-tags-data，根据 routePath 判断索引页（TagCloud）/详情页（PostList+TagList）。pageLayouts 加 tag: './layouts/Tag.js'。types.d.ts 修正 virtual-tags-data 声明
- **tags 插件**：addPages 改用 filepath=config.themeLayouts.tag + content=frontmatter（pageType: tag/tagIndex）。移除 markdown content/withBase/未用 import
- **TagList**：本地 generateTagSlug（带兜底），不 import shared（rspress 浏览器端限制）。ui package.json shared 移回 devDependencies

### 关键技术点
- rspress addPages filepath 指向 React 组件时，content 只需 frontmatter（如 home 机制）
- TagPageLayout 用 LayoutProps.routePath 解析 slug（routePath.split('/tags/')[1]）
- PostReference→Post 适配：补 url=route, filePath=''
- 虚拟模块 getRelatedTags 只接受 (currentTag, limit)（闭包含 allTags），非 utils.ts 的 3 参数版

## TagPageLayout 运行时修复 + Home 双栏侧边栏

### TagPageLayout 三个运行时 bug 修复
1. **routePath prop 不存在**：rspress addPages filepath 组件不通过 props 传 routePath，原解构 `{ routePath }` 为 undefined，`.split` 抛 TypeError 致空白。改用 `window.location.pathname`
2. **中文 slug 匹配失败**：window.location.pathname 返回 encodeURI 路径（%XX），allTags 的 slug 是原始中文。加 `decodeURIComponent`
3. **返回链接 404**：normalizeHrefInRuntime 只加 .html 不加 base，`<a>` 不经过 rspress 路由。改用 `usePageData().siteData.base` 手动拼接 `${base}/tags`

### Home 双栏布局（标签侧边栏）
用户要求 Home 左侧放标签侧边栏 + 未来合集占位。发现 theme.css 已预留 `.content-layout { grid-template-columns: 1fr 300px }` 但 Home 用 .home-layout 单列没用上。
- Home.tsx 改双栏：aside（TagCloud 标签云 + 合集占位）+ main（PostList）
- theme.css 加 .home-content grid（240px + 1fr）、.home-sidebar sticky、响应式 768px 单列
- 交互：点击标签跳转 /tags/:slug（复用标签详情页，用户选定方案）
- TagCloud 组件不再是孤儿：Home + 标签索引页都用它

### Home 侧边栏未生效的根因与修复
用户反馈标签区仍在文章上方。排查发现：lucid 的 `theme.css` 虽通过 `globalStyles` 声明，但 `packages/core/src/node/config.ts` 的 `createThemePlugin` 没有把 `theme.globalStyles` 传给 Rspress 的 `globalStyles` 配置，导致 theme.css 从未被 dev server 加载，`.home-content` grid 样式不存在。
- 修复：`createThemePlugin` 增加 `globalStyles: theme.globalStyles?.[0]`
- 同时 lucid 的 `package.json` build/dev 脚本增加 `cp src/theme.css dist/theme.css`，确保 dist 包含 theme.css（rslib 不会自动复制）
- 清理 blog/.rspress 缓存并重启 dev server 后，styles.css 中已出现 .home-content / .home-sidebar 规则，侧边栏应显示在左侧。

### Home 布局二次优化（header 内嵌 + 间距收窄）
用户反馈：header 横跨整页导致左侧标题下方悬空空白；"最新文章"应放进文章区内侧。

- 效果：侧边栏（标签+合集）从内容顶部起排且无悬空；标题仅出现在右侧文章区

### 隐藏 Rspress 默认文档侧边栏
用户发现左侧仍有 320px 的 `aside.rspress-sidebar` 占位，这是 Rspress 默认文档导航栏。Home/Tag 页是自定义布局，不需要它。
- core `createThemePlugin` 首页 frontmatter 增加 `sidebar: false`（同时修正原本 `---npageType...` 为合法 YAML）
- tags 插件生成的索引页和详情页 frontmatter 增加 `sidebar: false`
- 重启后 Rspress 默认 sidebar 应不再渲染，左侧空白消失。

### Rspress 默认 sidebar 仍未消失的根因（CSS 全局隐藏）
`sidebar: false` 没生效，因为 cogita core 根本没把 `themeDir` 传给 Rspress，所以 Rspress 一直在用 `@rspress/theme-default` 的 Layout——里面固定渲染一个空的 `aside.rspress-sidebar` 占 270~320px。frontmatter `sidebar` 只控制这个 sidebar **要不要显示菜单项**，不会让 aside 消失。
- 试过设置 `themeDir` 让 Rspress 用 lucid 自带 Layout.tsx，但 lucid 没导出 rspress 需要的全部组件（`Layout`/`useThemeState`/`Tag`/`Link` 等），构建直接 ESModulesLinkingError 报错
- 最终方案（适合 blog 项目，无文档侧边栏需求）：theme.css 全局隐藏
  ```css
  aside.rspress-sidebar { display: none !important; }
  :root { --rp-sidebar-width: 0px; --rp-nav-width: 0px; }
  ```
  让 rspress 默认 sidebar 节点直接消失且 grid 也不留空列

### 关键教训
- cogita 这种"自定义 React 布局"架构，要么完整导出 `@theme` 全部组件（很重），要么直接走 CSS 隐藏默认 chrome
- blog 项目无 doc 侧边栏需求时，全局 CSS 隐藏最简单

### Home 内容区加宽
用户反馈：隐藏默认 sidebar 后整页只剩中间一半有内容，两侧空白过多。
- `.home-layout` 加 max-width: 1400px、margin 0 auto、padding 0 1.5rem
- `.home-content` 列宽 260px→280px、gap 2rem→2.5rem
- 效果：整页内容更舒展，标签栏 280px、文章区吃满剩余空间

### 打破 rspress .rspress-doc 992px 限制
用户反馈加宽后仍无变化。根因：自定义布局被包在 `.rspress-doc` 里，rspress 默认给 `.rspress-doc` 设了 `max-width: min(100%, 992px); margin: auto`，外层约束导致 `.home-layout` 的 max-width:1400px 无效。
- 修复：theme.css 加 `:has()` 选择器精准打破限制
  ```css
  .rspress-doc:has(.home-layout), .rspress-doc:has(.tag-page) {
    max-width: none !important; margin: 0 !important;
  }
  ```
